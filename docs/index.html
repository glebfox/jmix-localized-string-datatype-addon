Jmix LocalizedString Datatype

Locale-aware entity text for Jmix apps. Store multilingual values as one attribute, edit them in Flow UI, validate every locale, and sort by the current user's language.

What it solves

Multilingual entity fields without custom screens for every project.

01

Use one domain type

Add a LocalizedString attribute to your entity and keep every locale together in one Jmix datatype.

02

Edit all locales in place

Attach value_localizedStringEdit to a ValuePicker and open a focused dialog for localized values.

03

Respect the user locale

Visual components display the value that matches the current locale, with sorting support for list views and data containers.

Flow UI editor

A localized editor that feels native to Jmix screens.

The add-on provides a ready-to-use action for ValuePicker. It can switch between compact and multiline fields, check unsaved changes, and accept custom validators or field providers when a project needs richer input controls. 

<valuePicker id="nameField" property="name">
    <actions>
        <action id="localizedStringEdit" type="value_localizedStringEdit"/>
        <action id="clear" type="value_clear"/>
    </actions>
</valuePicker>

Validation

Validate every localized value before saving.

Required values

Use @LocalizedStringNotNull, @LocalizedStringNotEmpty, or @LocalizedStringNotBlank to enforce locale coverage.

Length and pattern rules

Apply @LocalizedStringSize, @LocalizedStringLength, and @LocalizedStringPattern to each localized value.

Custom field behavior

Install validators or a field provider to customize the edit dialog while keeping the same entity attribute model.

Storage model

Database state stays simple.

Localized values are stored as JSON in one column, for example {"en":"Keyboard","de":"Tastatur"}. Filtering by this datatype is intentionally limited: Jmix GenericFilter and PropertyFilter do not support it.
